# BasketballWearShop

BasketballWearShop — это веб-приложение для электронной коммерции, предназначенное для продажи баскетбольной одежды, обуви и экипировки.

## Функциональность
- **Каталог товаров:** просмотр товаров, фильтрация и карточка товара.
- **Корзина:** добавление товаров, управление содержимым.
- **Оформление заказов:** создание заказа и выбор адреса доставки.
- **Личный кабинет:** управление адресами, история заказов, просмотр статуса.
- **Подарочные сертификаты:** покупка и активация.
- **Система достижений (Бейджи):** геймификация для пользователей.
- **Административная панель:** управление товарами, просмотр статистики заказов.
- **Внешние интеграции:**
   - Отображение актуальной турнирной таблицы НБА.
   - Хранение изображений товаров в AWS S3.

## Стек технологий
- **Backend:** Java 17/21, Spring Boot (Spring Web, Spring Data JPA, Spring Security).
- **База данных:** PostgreSQL, Liquibase (миграции).
- **Frontend:** Thymeleaf, HTML/CSS, JS.
- **Хранилище:** AWS S3 (для изображений).
- **Сборка:** Maven.
- **Инфраструктура:** Docker, Docker Compose.

## Структура проекта
- `src/main/java/.../models/` — доменные сущности (JPA Entities).
- `src/main/java/.../repositories/` — слой доступа к данным (Spring Data JPA).
- `src/main/java/.../services/` — бизнес-логика.
- `src/main/java/.../controllers/` — слой обработки HTTP-запросов (REST/MVC).
- `src/main/resources/db/changelog/` — скрипты миграции базы данных Liquibase.
- `src/main/resources/templates/` — HTML-шаблоны Thymeleaf.
- `src/main/resources/static/` — статические файлы (CSS, JS, изображения).

## 12-Factor App
Проект спроектирован с учетом методологии [The Twelve-Factor App](https://12factor.net/):
1. **Конфигурация:** Настройки и секреты передаются через переменные окружения (см. `docker-compose.yaml`).
2. **Backing Services:** БД и S3 подключаются как внешние ресурсы по URL/кредам из окружения.
3. **Stateless:** Приложение не хранит состояние (корзины и сессии хранятся в БД).
4. **Port binding:** Приложение самодостаточно и слушает порт, переданный в переменной `SERVER_PORT`.
5. **Logs:** Логи выводятся в `stdout`/`stderr` (настроено в `logback-spring.xml`).

## Запуск проекта локально (Docker)

Для запуска проекта локально потребуется **Docker** и **Docker Compose**.

1. Убедитесь, что порты `8080` (приложение) и `5432` (PostgreSQL) свободны.
2. При необходимости задайте переменные окружения для AWS S3 в файле `docker-compose.yaml` (или в локальном `.env` файле, если настроили).
3. Выполните сборку и запуск контейнеров:

```bash
docker-compose up --build
